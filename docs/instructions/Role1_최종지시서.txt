## 현재 Python 인터페이스

- `Component`는 `register(registry)`, `residual(t,y,ydot,context)->1-D np.ndarray`를 구현한다. `name`, `key(variable)`, `ports()->Mapping[str,port]`, `residual_ids()->tuple[str,...]`, `residual_scales()->1-D np.ndarray`, `outputs(t,y,context)->dict`가 공통 메서드다. 기존 데모 호환용으로 ID/scale 생략이 허용되지만 새 모델은 고정 순서의 고유 ID와 양의 물리 scale을 명시한다. `key()`는 `{instance}.{variable}`을 만든다.
- `StateRegistry.register(name, *, kind, initial, unit, shape=(), scale=1.0, owner=None)`에는 독립 `differential`/`algebraic` 상태만 등록한다. `alias(name,target)`은 미지수를 늘리지 않는다. 모든 Component 등록 후 Assembly가 `freeze()`하고 포트를 검사한다. `registry.get(y,key)`, `initial_state()`, `differential_mask()`, `scale_vector()`를 사용한다. Parameter/External Input/Derived/Alias/Residual/Diagnostic은 독립 상태가 아니다. 전역 `p_sys`는 지정 lower-plenum의 Role 2 Component가 `owner="primary_loop"`, `kind="differential"`로 한 번 등록하고 Role 5 builder가 유일성을 검사한다.
- `SystemAssembly(components, *, context=None, connections=(), thermal_links=())`에는 대표 Component만 넣는다. `residual(t,y,ydot)`는 고정 순서의 전역 `F=0`이고 `residual_details()`는 `(residual, ids, s_R)`를 같은 순서로 반환한다. `diagnose_jacobian(t,y,ydot,cj=...)`은 `diag(1/s_R)(F_y+cj F_ydot)diag(s_y)`의 rank/condition을 진단한다. 잔차 평가의 `y`,`ydot`은 읽기 전용이며 현재 trial에서만 값을 계산한다. 전체 미지수 수와 잔차 수는 같아야 한다. 이 조건만으로 정칙성이 증명되지는 않는다.
- `SimulationContext(registry, config={}, scenario={}, providers={}, heat_rates={})`는 읽기 전용 설정과 주입 provider를 담는다. Assembly가 자신의 Registry로 다시 바인딩한다. 기존 데모는 bare `StateRegistry` context도 사용한다. 각 Component는 `context.registry.get(...)` 또는 호환 `context.get(...)`으로 현재 trial을 읽는다. `with_heat_rates()`는 새 context를 만든다. 모델 안에서 시간 적분, Newton 반복, 상태 변경, 파일 쓰기, 이전 평가값 캐시를 하지 않는다.
- 유체 포트는 `FluidStreamPort(p,m_dot,h_outflow,h_instream,medium="helium")`이고 네 필드는 등록된 스칼라 SI 키다. `m_dot>0`은 **해당 장치로 유입**이다. `h_instream`은 독립 대수 상태이며 연결식이 결정한다. 같은 junction의 어느 `h_outflow`와도 같은 상태를 가리킬 수 없다. `StreamJunction(name,ports,mass_flow_epsilon,pressure_scale,flow_scale,enthalpy_scale)`은 압력 `N-1`, 유량 `1`, 유입 stream `N`의 `2N` 잔차·ID·scale을 제공한다. `mass_flow_epsilon>0`은 검증된 정격 유량과 `eps_mdot_rel`에서 정한다. 서로 다른 매질은 연결하지 않는다. 압력손실은 장치 운동량식에 둔다. 구형 `FluidPort` 두 포트 식은 데모 호환용이다.
- 온도 차가 있는 경계는 `ThermalSurfacePort(T,index=None)`와 `ThermalLink(name,transfer)`를 쓴다. `T`는 등록된 K 상태이며 배열의 한 셀은 `index`로 지정한다. `port.temperature(y,registry)`가 스칼라 값을 읽는다. `transfer(t,y,context)->(to_a,to_b)`는 각 격자의 비어 있지 않은 유한 1-D W 배열을 반환하고 `sum(to_a)+sum(to_b)=0`이어야 한다. Assembly가 링크별로 **잔차 평가당 한 번** 계산해 `context.heat_rates["{name}.to_a"]`, `["{name}.to_b"]`로 양측에 전달한다. 장치 잔차는 받은 열률을 한 번만 반영한다. `thermal_links` 사용 시 context는 `SimulationContext`여야 하며 `None`이면 Assembly가 생성한다. 동일 온도 노드의 이상 연결만 `ThermalPort(T,Q_dot)`/`ideal_thermal_two_port_residual`을 사용한다. 이때 `Q_dot`은 등록된 스칼라 대수 상태와 정의 잔차가 필요하다. Derived 열률에는 `ThermalPort`를 쓰지 않는다.

## 공통 Physics와 Composite

- `physics/`는 장치 상태·시나리오·시간적분에 의존하지 않는 현재 입력의 순수 계산이다. `interfaces.contracts.HeliumProperties`는 `temperature(p,h)`, `enthalpy(p,T)`, `density(p,h)`, `viscosity(p,T)`, `conductivity(p,T)`, `cp(p,T)`, `cv(p,T)`, `drho_dp(p,h)`, `drho_dh(p,h)`를 요구한다. SI와 NumPy broadcasting을 따른다. 실제 생산용 EOS는 미구현이고 `tests/fixtures/providers.py`의 물성은 합성 시험용이다. `HeatTransferCorrelation.coefficient(state,geometry)->h_conv`는 W/(m²·K)를 반환한다.
- `physics.heat_transfer` 또는 `.base`의 공개 함수는 `conduction(T_a,T_b,k,A,L)`, `convection(T_a,T_b,h_conv,A)`, `radiation(T_a,T_b,epsilon,A,sigma)`, `heat_transfer_coefficient(Nu,k,D_h)`다. 열률 부호는 a→b 양수 W, 온도는 절대 K. 현재 wrapper/서명만 있고 실제 Role 3 커널은 `NotImplementedError`다. Role 4의 SG 전용 상관식도 미구현이다. 상관식 유효 범위와 저유량/역류·층류/천이·자연대류 처리를 검증하고 장치 파일에 공통 식을 복제하지 않는다. `mode_nu`, `include_nc`, `mode_friction`, `mode_he_eos`, `mode_sg_he_crossflow` 등은 builder에서 provider를 선택하는 설정이지 DAE 상태가 아니다.
- `Core(config=None,properties=None,*,fluid=None,solid=None,power=None,coupling=None,name="core")`는 **이미 구현된 상위 조립기**다. `Core`만 Assembly에 등록한다. 등록·잔차·ID·scale 순서는 fluid→solid→상태가 있는 power다. fluid/solid는 `register`, `residual(t,y,ydot,context,*,heat_rate)`, `ports`, `residual_ids`, `residual_scales`, `outputs`를 구현한다. `coupling.evaluate(t,y,context)->(Q_to_fluid,Q_from_solid)`의 두 W 배열은 격자가 달라도 총합이 같다. `power.evaluate(t,y,context)`는 고체 격자의 W 배열이다. Core는 fluid에 `Q_to_fluid`, solid에 `power-Q_from_solid`를 주입한다. 상태 있는 power만 `register/residual/residual_ids/residual_scales`를 함께 제공한다. Core의 외부 열경계 추가량은 solid가 현재 `context.heat_rates`에서 읽어 자기 격자에 보존적으로 매핑한다. 물리식은 Roles 2/3이 구현한다.
- `HeatExchanger(config=None,properties=None,*,helium_side=None,wall=None,secondary_side=None,coupling=None,name="heat_exchanger")`는 **이미 구현된 상위 Composite**다. 상위 객체만 Assembly에 등록하며 helium_side→wall→secondary_side의 상태·잔차·ID·scale·outputs와 하위 외부 포트를 조립한다. `coupling.evaluate(t,y,context)`는 `(to_helium,to_wall_from_helium,to_wall_from_secondary,to_secondary)`의 보존적인 1-D W 배열을 반환하고 상위는 두 wall 배열을 더해 `heat_rate=`로 전달한다. Role 4는 세 하위 물리 모델과 coupling을 구현해 `physics.heat_transfer`를 사용한다. 하위 Protocol은 실제 모델이 아니다. `Piping`, `Plenum`, `Compressor`, `Vessel`, `RCCS`, `Boundary` 역시 현재 placeholder다. `models/thermal_link.py`의 열률 전달 골격은 완료됐다.

STEP 01C의 기존 62셀 차이·수정 근거는 `docs/registry_patches/step01c_variable_sync_history.json`에 남겼다. 기존 이름·의미를 먼저 검색한다. 신규 항목이 필요하면 `docs/registry_patches/variable_patch_template.csv` 형식으로 자기 `roleN/variable_patch.csv`에 `add` 또는 `update`, kind·unit·shape·owner·Registry 여부·런타임 키·코드 참조·출처·기존/신규값·사유를 기록한다. 방정식은 `equation_patch_template.csv`에 ID·식·이산화·의존성·잔차 수·`s_R`·경계·근거·상태를 기록한다. 새 변수가 없으면 handoff에 `없음`을 기록한다. 마스터 CSV/Excel/방정식표 병합은 Role 5가 담당한다. 미정값은 `null`/빈칸으로 남기고 문헌 수치를 만들지 않는다.
- DASSL 호출은 `DASSL(..., residual_scale=assembly.residual_scales()).solve(assembly.residual,t_span=(t0,tf),y0=registry.initial_state(),differential_mask=registry.differential_mask())` 형식이다. `s_y=registry.scale_vector()`와 `s_R`는 다른 척도다. `solvers.initialization.consistent_initialize`는 미분 상태를 고정하고 대수 상태·미분 상태 변화율을 일치시키며, `solve_steady_state`는 `ydot=0` 평형을 푼다. 저마하수 공통 계약은 `rho_i=rho(p_sys,h_i)`, 국부 기준식 `p_fluid_cell[lower]-p_sys=0`, 각 셀 질량식 `V_i*(rho_p*p_sys_dot+rho_h*h_i_dot)+out-in=0`이다. `h_he`는 Differential, 국부압·기본 무관성 면유량은 Algebraic이며 `rho_he`·`M_he_loop`는 Derived다. 과도에는 모든 셀 질량식을 유지하고 전역 합은 진단만 한다. 정상 초기화에서 종속 국부 질량식 한 개만 검증된 `M_he_loop-M0=0` 또는 `p_sys-p0=0`으로 교체한다. 이 정상 제약과 국부 기준식은 별개다. 실제 HTGR rank와 물리식은 Role 2/5가 검증한다. Python 코드가 Modelica의 자동 flattening/index reduction을 제공하지 않는다.
- `python -m pytest -q tests/contracts`는 합성 flat/composite DAE, 접속·port·scale·ID, 열률, 폐루프 rank를 확인한다. `tests/fixtures/synthetic_models.py`, `synthetic_heat_exchanger.py`, `closed_loop.py`, `low_mach_loop.py`, `providers.py`, `synthetic_config.yaml`은 **가상 시험 자료**다. 실제 HTGR 정상상태나 LOFC 증거가 아니다. 역할별 물리 단독 시험 후 `python -m pytest -q`, `python main.py --demo`를 실행한다. `main.py --demo`만 현재 실행 가능한 계산이며 실제 scenario 실행은 Role 5의 후속 builder/runner 작업이다. 완료 보고에는 단독 시험과 실제 계통 통합 시험을 구분한다.


정확한 솔버 진입점은 `DASSL(*,dt=0.1,max_order=5,rtol=1e-5,atol=1e-8,min_step=0.0,max_step=np.inf,max_steps=100000,max_retries=12,newton_options=None,residual_scale=None).solve(residual,*,t_span,y0,ydot0=None,differential_mask=None,jacobian=None)`다. `solvers/initialization.py`의 `consistent_initialize(residual,t0,y_guess,differential_mask,*,ydot_guess=None,options=None,residual_scale=None,correction_scale=None)`와 `solve_steady_state(residual,t0,y_guess,*,options=None,residual_scale=None)`를 사용한다. `SystemAssembly.outputs(t,y)`는 후처리 dict를 반환한다.

## Role 1 — 형상·운전점·검증 자료

### 소유 범위와 산출물

수정 파일은 `config/geometry.yaml`, `config/operation.yaml`, `config/scenarios/steady_state.yaml`, `config/scenarios/loss_of_flow.yaml`, 새 `data/validation/` 자료 및 manifest, 입력 검증 테스트, `docs/registry_patches/role1/`, `docs/handoffs/role1.md`다. 현재 YAML은 대부분 `null`/빈 이벤트로 된 **양식**이다. `docs/config_schema.md`가 현재 키와 조건을 설명한다. `models/`, `physics/`, `interfaces/`, `system/`, `solvers/`의 구현은 담당하지 않는다.

1. 같은 MHTGR-350 참조 설계와 운전점의 원문을 확인한다. 변수표의 노심 정격 350 MWth·157.1 kg/s·6.39 MPa와 SG 단독 검산 352.193 MW·157.2 kg/s·6.31 MPa는 경계가 다르므로 하나의 초기상태로 합치지 않는다. 압력의 절대/게이지 기준과 측정 위치, 원 설계 개정, 단위 변환을 기록한다. 출처가 확인되지 않은 값은 미정으로 둔다.
2. `geometry.yaml`의 기존 `core.axial_cells/channel_length_m/flow_area_m2/elevation_profile_m`, `heat_exchanger.axial_cells/heat_transfer_area_m2`, `compressor.location` 키를 유지한다. Core 유로·우회로·플레넘·배관·SG·RPV·RCCS-0 모델에 실제로 필요한 체적, 수력직경, 면적, 고도와 재료 입력을 담당 모델의 요구 목록에 맞춰 추가한다. 셀 `(N,)`와 면 `(N+1,)` shape, 양수 기하, 출처와 환산 근거를 검증한다. 격자 크기는 Roles 2/3/4와 인터페이스를 맞춘다.
3. `operation.yaml`의 `reactor.initial_thermal_power_W`, `primary.initial_pressure_Pa/initial_temperature_K/initial_mass_flow_kg_s`, `compressor.initial_rotation_rate_rad_s`를 호환 유지한다. 정격 검산값과 시나리오 초기 추정값을 별도 필드와 근거로 구분한다. SG 열침원·순환기·RCCS 경계의 실제 요구 입력을 확인하고 미정이면 `null`로 남긴다.
4. `steady_state.yaml`과 `loss_of_flow.yaml`에 필요한 경계·사건·출력/잔열 이력의 출처를 기록한다. 트립, 감속, SG 경계, SCS 사용 여부, 가압 폐루프 조건을 검증 가능한 자료로만 채운다. 제어신호를 실제 질량유량으로 강제하지 않는다. 부분 유량 감소는 별도의 교육용 시험으로 구분하고, 실제 LOFC 이력이 없으면 실행 가능하다고 주장하지 않는다.
5. `data/validation/benchmark/`에 접근 가능한 원자료 또는 출처 manifest를 작성한다. 문헌·표·그림 위치, 디지털화 여부, 단위, 사용 모델의 초기/경계조건을 적는다. 기존 지시서의 조사 후보는 OECD/NEA NEA/NSC/R(2017)4, INL/EXT-10-19803, PHISICS/RELAP5-3D Exercises II-1/II-2이며 실제 원문을 확인한 뒤에만 채택한다. MHTGR-350 계산 결과와 HTTF/HTTR 실험을 혼동하지 않는다. 저작권 있는 논문 전체를 무단 저장하거나 시계열을 생성하지 않는다.
6. 새 입력 변수는 기존 372개를 먼저 대조해 role1 patch를 작성한다. `reference_value`·`initial`·`source`·`status`를 구분하고, 새 방정식을 만들지 않는 경우 `equation_patch.csv` 변경 없음이라고 handoff에 적는다. Role 2/3/4/5가 사용할 입력 키·단위·shape·출처·미정 항목의 표를 handoff에 남긴다.

### 검증과 PR

YAML 구문, 조건별 필수 키, 단위, 양의 기하, 셀/면 배열 길이, 출력분율 합을 입력 검증 테스트로 확인한다. 가상 수치는 테스트 fixture에만 둔다. 전체 `pytest`와 데모를 실행하고 실제 입력 부족으로 막힌 계통 경로를 구체적으로 보고한다. PR 제목 예: `data: add sourced MHTGR-350 geometry and scenario inputs`.
